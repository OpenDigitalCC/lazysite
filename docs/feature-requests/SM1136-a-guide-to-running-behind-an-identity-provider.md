# What happened

united/platform will put every service behind Authentik and use lazysite's
trusted-header route first (Caddy forward-auth to the proxy outpost). SM1128,
P1-7:

> A docs page, "Behind an identity provider", with the Caddy forward-auth example
> for Authentik and the security conditions (P1-1 list, private network).

The settings were spread over Authentication, Configuration and the security
architecture note, and the example in Authentication copied Authentik's headers
to the fixed names with no trust list and no mention of groups.

# What shipped

`starter/docs/behind-an-identity-provider.md`, installed into every site at
`/docs/behind-an-identity-provider`. It says what the route is; the settings
(`auth_proxy_trusted`, `auth_proxy_trusted_from`, `auth_header_*`,
`auth_header_groups_separator`, `auth_group_map`); what a directory group gives
(page and file access by name, capabilities and operator status only when the
operator marks the group, SM1135); sign-in and sign-out; the three conditions
(lazysite reachable only from the proxy, the trust list naming the proxy and only
the proxy, every path through the provider's check; an empty list believes
nobody); and a Caddy forward-auth example for Authentik's outpost with the
matching `lazysite.conf` (separator `|`, a mapped name). Host names are
placeholders (`example.org`).

It is listed in the docs index (`starter/docs/index.md`), linked from
Authentication and Configuration, and in `docs/INDEX.md` (regenerated by
`tools/gen-doc-index.pl`, which t/lint/110 checks).
