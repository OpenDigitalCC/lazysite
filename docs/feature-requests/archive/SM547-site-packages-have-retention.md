# The finding

`Manager/Backups.pm _apply_retention` (212-229) says in its comment that
it bounds `site` among the kinds it handles, but its only caller is
`action_backup_create` (`Backups.pm 630`). `SitePackage::package_create`
never calls it, so site packages accumulate without limit.

The probe set `backup_retention: 1`, then made three packages and three
manual snapshots. The three snapshots collapsed to one; all three
packages remained.

# Why it matters

Operability: this is exactly the disk-filling loop that SM268 03-F11 was
written against, and it is open on the artefact an agent produces most -
every `site_backup` call is a site package.

# The proving test

NEW single assertion: `backup_retention: 1` leaves one site package.

# Fix shape

Call `_apply_retention` for the `site` kind from `package_create`, as the
helper's own comment already promises.
