# What happened

The 0.15.9 walk, finding F-5:

> The `plugin-save` / `plugin-read` / `plugin-action` spelling still works but
> is audited `spelling=deprecated`. My scripts use it; the manager page may too.
> Noted in case the deprecated spelling is due to go.

The manager pages and assets already call `extension-*` (t/unit/manager/167
holds the pages to it). Inside the engine, only three comments in
`starter/manager/config.md` still named `plugin-save` / `plugin-read` /
`plugin-list`. The briefing a script author is given
(`starter/docs/ai-briefing-practice.md`) also teaches `plugin-list`,
`plugin-action` and `plugin-read`/`plugin-save`, and that is probably where
the reporter's scripts learned the spelling. That file is generated by
`tools/import-field-practice.pl` from the site agent's own files outside this
repo, and t/lint/89 forbids editing the served copy, so it cannot be changed
here.

# What shipped

- The three comments in `starter/manager/config.md` name the extension-*
  spellings.
- The old spelling still works and is still audited `spelling=deprecated`:
  external scripts use it, and removal is not scheduled here.
- t/lint/266 reads the deprecated set from the `plugin-*` keys of
  `lib/Lazysite/ControlApi/Actions.pm` (the set the API's own `\Aplugin-` test
  treats as deprecated) and fails if any file under `starter/` or `skills/` calls one. It exempts the generated briefing
  (recognised by its import checksum) until the source is changed and re-imported,
  the generated `docs/reference/control-api-actions.md` (which states that it
  lists the internal names), and audit-log wording in the top-level docs,
  which quotes what the audit really records.

# Open

The site agent's APP-PRACTICE.md source needs `plugin-list`, `plugin-action`,
`plugin-read` and `plugin-save` changed to the extension-* names; the next
import then carries it, and the two exemptions in t/lint/266 can go.
