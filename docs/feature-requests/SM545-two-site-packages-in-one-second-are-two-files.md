# The finding

`Manager/SitePackage.pm` builds the package name from the host and a
second-resolution stamp (`SitePackage.pm 204-206`) and writes it with
`tar czf` (`SitePackage.pm 392`), which overwrites. The O_EXCL claim that
SM268 03-F9 added to `Backups::_claim_name` was never carried across to
site packages.

The probe made two `package_create` calls in one second: both returned
`ok => 1`, with the same name, and one tarball remained - the first
silently replaced. The sidecar then describes whichever write won. The
manager UI cannot hit this by hand; an agent looping `site_backup` can.

# Why it matters

Correctness: a create that reports success has to leave behind the
artefact it reported. Two successes with one file means one backup the
caller believes exists is gone.

# The proving test

`bp-probe-package-name.t` as a test: two creates, two files.

# Fix shape

Carry the `_claim_name` O_EXCL claim across to `package_create`, so a
name is taken once and a collision picks a fresh one.
