Release 0.7.9 - permissions say what they mean: SM095 leftover sweep

Cleanup round from a live audit-trail finding. Channel: edge.

The finding
- Creating an AI account from the Users page still ran the pre-SM095
  per-account "webdav on" call: the backend rightly refused it, the page
  reported success anyway, and only the audit trail told the truth.
  Capability enforcement was never wrong (one group-only resolver
  everywhere); every leftover was in what the product SAYS.

Fixed
- Users page: AI-account creation relies on group capabilities alone,
  and a failed follow-up step is now reported instead of swallowed.
  Dead per-account toggle helpers removed.
- NEW shell verb `group-set GROUP KEY on|off` - the command every
  refusal (including the audit-trail reason) already told operators to
  run, but which only existed in --api mode. A regression test proves
  the refusal's advice works verbatim.
- CLI usage/help/error text for `set` now offers only account-shaped
  fields (ui, dav_scope, comment, email, expires_at); the unreachable
  per-account webdav branch is gone.
- Docs teach the group route: webdav.md's deploy-identity example,
  theme-publishing.md, the README AI-partner section (partner-create),
  and the onboarding brief's "ask the operator" wording.

Known gap (flagged, unchanged): the old per-account route refused a
webdav grant while webdav_enabled was off site-wide; the group route
has no such warning. Harmless - /dav 404s site-wide regardless.

Fleet: edge-channel sites pick this up on the next upgrade run; stable
sites stay on 0.7.8.
