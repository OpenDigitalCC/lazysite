Release 0.10.0 - STABLE: promotes the bedded-in 0.9.11-0.9.17 beta line to stable

Channel: STABLE. 0.10.0 promotes the beta line that ran from 0.9.11 through 0.9.17 -
the same code as 0.9.17, now certified for customer rollout - superseding 0.9.10 as
the stable release. No new functional change over 0.9.17, no BREAKING change, and no
migration (the durable stats store rebuilds itself from existing data on first run).
A stable build is accepted by every site (edge, beta and stable channels), so this
rolls out fleet-wide.

Operators on 0.9.10 (the previous stable) gain everything the beta line accumulated:

Reliability + security (0.9.11-0.9.13)
- Login-loop fixes (stale session marker; mcp-only/no-ui accounts get a clear message
  instead of a loop); raw-mode content-page write guard.
- Engine-served system pages (login/claim/40x) with a content-root -> docroot ->
  protected-default fallback, so a deleted or missing copy self-heals instead of 404ing
  (SM201). This clears the "system page missing" health warnings seen on 0.9.10 sites.
- Site-integrity + connector reliability: capability-aware discovery, permissions-grid
  correctness, migration completeness, clearer connector sign-in reasons.

Authoring + operator features (0.9.14-0.9.15)
- Theme-authoring API + Figma design ingestion (theme_tokens, create_theme, layout
  token vocabulary, the integrations namespace); sub-user promotion; content-history
  statistics; the Domains configure-modal and other manager-UI polish.

Access, discovery + analytics (0.9.16-0.9.17)
- Operator-set access-token lifetime with sliding renewal (no daily cron); code-served
  AI-partner discovery that advertises only enabled endpoints; tools/list discovery
  hygiene.
- Durable per-day visitor-stats store with month-on-month trends, self-describing data
  horizons, visitor-level scanner classification and a 404 plausible/junk split; the
  privacy commitment codified (lazysite installs no trackers; aggregates only;
  daily-salted keys).

Permissions robustness (0.9.17)
- Sudo-safe credential/settings/updater writes (a helper or upgrade run under sudo no
  longer leaves root-owned files the CGI cannot access), and a repair tool -
  lazysite-check --fix (front-ended by lazysite-fix-perms) - that re-asserts ownership
  and modes across lazysite/. Run it once on any 0.9.10 site whose lazysite/ ownership
  has drifted.

Security: the 0.9.x line's F1 hardening reaches the stable channel with this promotion.
From 0.9.4 STABLE the 0.9.0 posture is unchanged: remote surfaces (WebDAV, control API,
MCP, OAuth) are off by default; enable them in Settings -> Services.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
