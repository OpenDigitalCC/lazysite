Release 0.7.8 - STABLE: version recording guaranteed + Content history as a plugin

Field round 2, cured at source. All gates green; channel: STABLE.

Silent version-loss (found in live validation)
- A doctor chown could hand the git store to the site user, after which
  the CGI's commits failed forever - saves succeeded, versions silently
  vanished. Fixed at every layer: the repo is a proper shared repo
  (git forces group-writable objects regardless of identity), a failing
  add on an existing file is now LOUD, a COMMIT_FAILED breadcrumb makes
  ongoing failure visible, lazysite check FAILs with the real symptom
  ("new file versions are silently not recorded") and --fix repairs it,
  and the empty-history panel suspects failure instead of reassuring.
- The guarantee tier: a structural write-path registry (a future content
  write cannot ship unversioned), mixed-identity permanence verified
  empirically, and a lifecycle test proving the four reporting surfaces
  can never disagree.

Content history is a plugin now (owner feedback)
- It is not a backup - it is change logging. Enable it where features
  live: Plugin Manager -> Content history -> Enable (Plugin Config shows
  status, commit count and recording health). Its sibling Git sync sits
  beside it. The Backups page returns to being purely backups: the
  Content history card and the info-only "Themes & layouts" pointer are
  gone (Appearance carries the substance).

Fleet: sudo lazysite upgrade --all. Existing broken-repo sites (if any):
one `sudo lazysite check --docroot ... --fix` heals version recording.
