Release 0.7.25 - EDGE: forms discoverability + manager UI/key/WebDAV fixes

Channel: EDGE. A fixes-and-polish batch from 0.7.24 live-testing: native forms
are now discoverable where an agent acts, a machine key records its use over
every channel, WebDAV PUT stops failing under missing parents, and a run of
manager-UI corrections. Stacks on 0.7.24.

Native forms are discoverable where an agent acts (SM161)
- Agents were hand-writing dead <form> HTML instead of using the native :::form
  + bind_form flow, because the good guidance lived on bind_form (the finish
  line, reached too late). The create_page / write_file tool descriptions and the
  MCP initialize instructions now say plainly: never hand-write a form; use
  create_form or a :::form and then bind_form.
- A new create_form tool scaffolds a native form and points straight at
  bind_form. validate_page warns on hand-authored, mailto: and third-party
  (Google Forms / Typeform / etc.) forms - the last a data-governance leak - and
  on unbound :::form blocks. audit_site gains a broken_forms category.
- Also fixes a fence bug where :::form written with no space (as the docs wrote
  it) rendered as literal text.

A machine key records its use over the API and WebDAV (SM163)
- A key could show "not used yet" while it was actively reading over WebDAV,
  because use was stamped only on the MCP connector path. Every credential path -
  control-API token, WebDAV Basic auth and MCP - now records use, throttled to at
  most one write per window.

WebDAV PUT auto-creates the missing parent chain (SM166)
- A PUT under a missing collection returned 409 (one level missing) or a
  confusing 502 (several). It now creates the parent chain (mkdir -p), confined
  to the docroot and refused for a traversal path, so a deep PUT just works.

Manager UI fixes from 0.7.24 testing
- The file editor no longer false-warns about "unsaved changes" on load (SM170).
- The Sessions / Keys tables scroll within their box on narrow screens (SM171).
- The audit page gains an auto-refresh (10s) checkbox (SM172).
- The Domains form uses one "Layout / theme" selector instead of two, so you
  can't pick a theme without a layout (SM167).
- Folders get an actions dropdown (rename/move, delete), like files (SM162).
- The Domains edit row now exposes every field the add form does: the content
  folder is editable (repoint a domain, with a note that it does not move files),
  and "searchable by default" is a true/false dropdown rather than a text box
  (SM174).
