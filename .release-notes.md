Release 0.7.17 - EDGE: domains admin (agency multi-domain management, SM154)

Channel: EDGE - stacks on 0.7.16. The agency multi-domain admin plane on top of
the SM151 serving plane.

The hard line
- lazysite owns ONLY the lazysite side: registering a domain (alias.<host>.*
  in lazysite.conf) and its content-root directory. DNS, the web-server domain
  alias and TLS are a precondition (operator / Hestia / an external control
  panel), never touched by lazysite. A future external panel drives both the
  Hestia CLI and the lazysite CLI in one deploy.

P1 - confinement spine
- A domain-bound (dav_scope) editor is now confined to their content_root on
  the interactive manager channel too, not just WebDAV/token. One shared
  confinement helper across every channel; operators are unconfined.

P2 - engine + CLI + control-API
- Lazysite::Manager::Domains: register/list/configure/remove a domain, strict
  host + content-root validation, in-place conf writes (mode/group preserved),
  remove keeps content unless --purge.
- tools/lazysite-domains.pl: a scriptable CLI (list/add/set/remove, --json).
- manager domain-add/set/remove control-API actions, manage_config-gated,
  POST-only. A domain registered via the engine is served by the SM151
  processor under its Host header.

P3 - panel + gated nav + auto-scoping
- The Domains page is a full CRUD panel. The nav entry shows only to a user who
  may manage domains. A bound editor's file browser roots at their own domain's
  content_root (home_domain + dav_scope). home_domain is a settable account key.

Delegation model
- Bind a client account with: home_domain = clienta.com, dav_scope =
  content/clienta. The account is then confined to that content root everywhere
  and its manager UI is rooted there; the agency super-admin (no binding) sees
  and manages all domains.

Verification
- Full suite green; bench within tolerance; coverage gate green; perltidy +
  perlcritic clean. No restore rehearsal (per-stable-cycle only; this is edge).
