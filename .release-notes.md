Release 0.9.14 - EDGE: theme-authoring API + Figma design ingestion, operator features

Channel: EDGE. A large feature release on top of 0.9.13, led by the theme-authoring
API and the Figma design-ingestion method, plus operator-facing features and
manager/connector fixes. No BREAKING change and no migration. Edge-channel sites
take this first; beta and stable sites are unaffected until it promotes.

Theme authoring + Figma design ingestion
- theme_tokens (SM204): a new MCP read tool that returns a layout/theme's token
  vocabulary in one call - the first call of any restyle or design transfer,
  replacing path-guessing + read_file + CSS grep. Falls back to a derived
  vocabulary when a layout declares none.
- create_theme (SM205): a new MCP write tool that scaffolds a validated theme
  (config plus optional CSS, copying the layout's default CSS when omitted) in one
  call, with eager name/value validation; theme.json written via write_file now
  runs the same validator eagerly, ending the fix-then-reactivate trap.
- Declared token vocabulary (SM203): layout.json gains an optional, declarative
  tokens block; activating a theme that mis-supplies a layout's declared tokens
  logs a non-fatal warning. The render-time emission is unchanged.
- Layout catalogue (SM206): list_layout_catalogue now carries a per-layout
  description and tags, so an agent can choose a base layout without installing it.
- layout.tt is readable (SM202): read_file (and history view/restore and WebDAV)
  no longer refuse a Template Toolkit layout.tt as binary, unblocking the
  copy-nearest-layout-then-adapt authoring workflow over the connector.
- Integrations docs (SM208): a new /docs/integrations/ namespace with a Figma
  helper documenting the dual-MCP method - bridge the Figma MCP (source) and
  lazysite (destination) in one session; extract tokens/structure/screenshots,
  translate identity to tokens, rebuild rhythm/scale in CSS. Registered for
  llms.txt and sitemap, cross-linked from the briefing set, with a build-from-figma
  connector recipe.

Operator features
- Promote a sub-user to top level (SM194): clear an account's managing parent
  (operator-only), with a separate, explicit "independent of creator" control that
  lifts the created_by scope ceiling - two deliberate choices, both on the Users
  page; provenance (created_by) is never rewritten.
- Content-history statistics (SM199): a file-list overview of the content history -
  per-file revision count, first and last revision dates and last author, plus a
  site summary - as a Files-page "History overview" panel, a git-history-summary
  control-API action and a list_content_history MCP tool. Counts follow renames and
  never leak across a delete/recreate boundary (the 0.7.x rename-aware lineage).

Manager + connector fixes
- The deploy-time discovery check now accepts the house-standard dynamic
  ${REQUEST_SCHEME}://${SERVER_NAME} site_url (it resolves to https under TLS),
  ending the false "not https" warning that fired across the fleet.
- A passwordless / token-only account can now be removed (it was wrongly reported
  "not found").
- An authenticated account without the ui capability that reaches /manager/ now
  gets a clear terminal message ("this account cannot use the manager - connect via
  the connector") instead of a login loop; and the Users page warns before a group
  change would remove an account's last manager-access group.

From 0.9.13 the 0.9.0 posture is unchanged: remote surfaces (WebDAV, control API,
MCP, OAuth) are off by default; enable them in Settings -> Services.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
