Release 0.10.1 - EDGE: form spam controls, submissions tooling, and fixes

Channel: EDGE. 0.10.1 is an edge build on top of 0.10.0 stable - a batch of
operator-facing form/submissions features, an agent-facing read action, a
recent-change marker, and one fix. No BREAKING change and no migration (the new
form-event log and quarantine flags are created on demand). Edge sites take it on
their next update; beta and stable sites stay on their channel until it promotes.

Forms: spam controls that keep the privacy stance (SM216)
- Suspect submissions are QUARANTINED, not silently delivered. The form handler
  scores each submission server-side at accept time (more URLs than a per-form
  threshold, default 2; an optional per-form keyword list) and, when it trips,
  STORES the message but flags it - held out of the notification bell and shown
  under a Quarantine filter in the Submissions viewer, where one click Confirms
  (un-quarantines) or Deletes it. A false positive still arrives, just
  unannounced, which is what makes the heuristics safe to run on by default. This
  holds the published stance in full: no third-party anti-spam or CAPTCHA, no
  fingerprinting, no JavaScript requirement, no accessibility regression -
  everything is server-side and content-based.
- Blocked-vs-stored visibility. Every submission outcome (delivered, quarantined,
  or blocked by a control - honeypot / token / too-fast / expired / rate) is now
  counted into the durable per-day stats store (SM213), so the visitor-stats
  report shows what the form controls stopped instead of it dying silently into a
  log. Counts only - no submission content, no IP addresses.

Submissions viewer: bulk cleanup + export (SM187)
- Select rows (or select-all) and Delete them in one atomic operation, and
  Download the store as a CSV built in the browser from the loaded rows. Bulk
  delete is operator-only and audited, like the single-row delete.

Agents: read which forms exist, least-privilege (SM214)
- A new form-list read action (control API) and a form_list MCP tool let a
  purpose-built agent discover a site's forms - names, handler types, whether a
  submissions store exists and how many rows - under the read_submissions
  capability, without the broader manage_forms. PII-free: names and counts only.

Manager: recent-change marker on Groups (SM103)
- The recent-change dot (already on the Files and Users pages) now also marks a
  group whose settings or capabilities changed within the window, with a
  who/when/what tooltip.

Fix
- Sessions & keys: extending an access-token lifetime now routes through the
  correct control-API action, so the change applies instead of failing with an
  "Unknown action" audit entry (SM212 follow-up).

Also: SM185 and SM186 roadmap items marked shipped (their follow-ups were already
delivered); a new SM217 candidate captured (first-class domain aliases). No code
change from those.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
