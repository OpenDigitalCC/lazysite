Release 0.7.27 - EDGE: multilingual language sets + subdomain delete-safety + domains UX

Channel: EDGE. Multilingual sites as a first-class feature - sibling domains, one
per language, linked as one language set with engine-supplied switcher data,
hreflang and a file-based translation workflow - plus subdomain-aware theme/layout
delete-safety and a run of Domains UX fixes. Stacks on 0.7.26.

Multilingual sites: language sets over the multi-site plane (SM179)
- A set of sibling domains - one per language, each its own content root - can be
  linked as one language set (a shared lang_group). The engine knows the siblings,
  so every layout gets ready-made switcher data in [% languages %]: each
  language's URL for the current page, the current one flagged, and whether the
  translation exists. The built-in layout renders a switcher plus hreflang
  alternates and an x-default; per-domain sitemaps gain xhtml:link hreflang
  alternates for pages whose counterparts exist.
- A page's language (lang:, site-wide or per host, overridable in front matter)
  surfaces as <html lang> and a Content-Language header. A json: source resolves
  against the content root first - so a translated page reads its own data - then
  the docroot. Layouts localise their own chrome via
  layouts/<layout>/strings/<lang>.json into [% t %], with per-key English fallback.
- Coverage is visible and re-runnable: a read-only lang-status action (and a
  Domains "Language coverage" panel) reports each language root's current / stale /
  missing pages, so a translator re-does exactly what changed. whoami and the MCP
  announcement tell an agent the set exists, where each language's files live, and
  the rule: translate values, never keys/paths/structure, and never hand-build a
  switcher or hreflang. Engine-chrome localisation (login/validation/404) is
  deferred to a later release.

Theme/layout deletion accounts for every domain (SM177)
- Delete-safety now scans every registered domain (base plus sub-domains) and
  refuses - naming them - while any domain uses the theme or layout, resolving each
  host's effective values. Previously only the primary's active choice was
  considered, so a theme/layout a sub-domain used could be deleted out from under
  it.

Domains UX
- Audit log: a domain action's target (a host) no longer opens in the file editor;
  it links to the Domains page (SM178).
- The domain access lists ("Groups allowed to manage", "Users locked to this
  domain") are tick-lists of the site's real groups/accounts, not free text.
- The domain edit panel is grouped into aligned Identity / Presentation / Access
  sections.
