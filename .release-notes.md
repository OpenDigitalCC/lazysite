Release 0.9.15 - BETA: manager UI polish (domains configure-modal, promote-in-dropdown, hints) + docs

Channel: BETA. A low-risk manager-UI and documentation release on top of the 0.9.14
edge line. No engine change, no BREAKING change and no migration; the changes are
UI, copy and documentation only. Beta-channel sites take this; stable sites are
unaffected until it promotes.

Manager UI
- Domains page - one Configure modal per domain: each domain row now opens a single
  full-width Configure sheet (the same modal used for account configuration),
  replacing the per-row Actions dropdown plus the inline edit panel. Controls are
  grouped - Identity (address, title, content folder), Presentation (layout + theme,
  nav, search), Access (allowed groups, locked users), Language (lang / lang_group) -
  with a Tools footer (Preview, Check, Export) and a separated Danger zone (Delete).
  The domain row is slimmed to the essentials plus a state chip.
- Users page - promote in the parent dropdown: promote-to-top-level is now a choice
  in the Parent "move under" dropdown (operator-only, shown when the account is not
  already top-level) rather than a standalone button; the separate scope_independent
  toggle is unchanged.
- Copy fixes: the WebDAV password hint now reads correctly for an AI account (which
  has no account password), pointing at the access token under "Connect an AI
  assistant"; the Add-domain content-folder placeholder drops the stale sites/
  prefix.

Documentation
- The complete feature reference (docs/FEATURES.md) is brought current to 0.9.14 -
  the theme-authoring API and dual-MCP Figma ingestion, plus the whole 0.8/0.9 line
  (multilingual and system pages, domains administration, security and capability
  hardening, the submissions viewer, site-package migration, connector reliability,
  content-history statistics, sub-user promotion) and the version timeline. This is
  the source the public feature page is summarised from.
- Backlog: SM210 (tools/list returns the full tool list to an unrecognised token -
  discovery hygiene, not a hole) logged; SM211 (a WebDAV lazysite/ write-guard
  finding) investigated and parked - the authorise_layout guard is correct and the
  nav.conf / forms carve-outs are deliberate.

From 0.9.14 the 0.9.0 posture is unchanged: remote surfaces (WebDAV, control API,
MCP, OAuth) are off by default; enable them in Settings -> Services.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
