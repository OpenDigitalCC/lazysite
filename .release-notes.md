Release 0.7.1 - Persistent runtime: FastCGI worker pools (SM142)

The processor now runs as a persistent FastCGI worker when spawned with a
listen socket (spawn-fcgi convention); plain CGI remains the default and is
byte-identical to before - FCGI.pm is lazy-required, so nothing new is
needed on CGI-only hosts. All gates green; channel: edge.

- Accept loop with per-request state hygiene inside the loop
  (reset_request_state, access record, die-guard - one shared
  handle_one_request for both paths).
- Prefork pools via FCGI::ProcManager (LAZYSITE_FCGI_WORKERS); worker
  recycling via LAZYSITE_FCGI_MAX_REQUESTS (default 500).
- Measured: cache-hit 62.2 ms plain CGI -> 0.4 ms FCGI (147x, mean of 50).
- Tested over the real FastCGI protocol with an in-tree minimal client;
  state isolation across consecutive requests is pinned (status, body,
  access-log lines, visitor keys, cache flag, UTF-8 output).
- The auth wrapper stays CGI in this phase (manager traffic un-pooled);
  the visitor-facing hot path is the pooled one. Packaging (systemd pool
  units, proxy_fcgi vhost config) ships with SM139.

Optional host packages for pooling: libfcgi-perl, libfcgi-procmanager-perl.
