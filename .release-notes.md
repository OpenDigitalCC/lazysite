Release 0.6.5 - manager_groups retired + fresh-install robustness

A breaking-change release with an automatic migration, plus the field-report
fixes from a real fresh-install round. All gates green; channel: edge.

BREAKING - manager_groups retired (SM138)
- Manager access is granted by GROUPS only: the `ui` capability (manager UI) and
  `manage_users` (operator powers), managed on the Groups page. The legacy
  `manager_groups:` key in lazysite.conf is retired.
- Migration is AUTOMATIC: on the first settings read after upgrade, any group
  the key named receives the full manager grant explicitly (every capability
  except the remote api/mcp channels - manager groups are interactive-only) and
  the conf line is removed. Effective access is unchanged; no operator action.
  See UPGRADE.md.
- The unsecured/dev mode is now "no group grants manager access" (previously
  "manager_groups unset"): same dev experience, but manager access is always
  visible in the permissions grid - no more invisible conf-conferred rights.

Fresh-install robustness (field reports)
- setup-manager guarantees the admin group's capabilities, and a manager group
  with no capability entry SELF-HEALS on any settings read - closing the trap
  where a fresh install's manager could not even add a user.
- install.pl sets lazysite.conf to 0664 and, when run as root, aligns ownership
  of the lazysite/ tree to the docroot owner - the manager can write settings
  regardless of which deploy wrapper (if any) ran a chown pass afterwards.

Manager UI fixes
- Browser autofill no longer stuffs the operator's saved login into the Users
  page inputs (the Rename box showed "manager") or plugin credential fields.
- The notification bell is grey when nothing is unread; its colour returns with
  the unread badge.
- notify-xmpp config: the recipient field is labelled "Recipient JID"; the
  sender nickname defaults to the site name (sanitised).
