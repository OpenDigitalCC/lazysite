Release 0.6.8 - First-party analytics: stats work out of the box

Visitor statistics no longer require any web-server setup. All gates green;
channel: edge.

First-party analytics (SM140 increments 1+2)
- The processor records its own traffic: one anonymised JSON line per request
  to lazysite/logs/access-YYYYMMDD.jsonl. Every page view (cache hits
  included), every clean-URL 404 and scanner probe - complete for visitor
  metrics with NO access-log ACLs, no vhost changes, and no nginx-vs-apache
  undercount.
- Privacy by construction: the visitor key is a daily-salted keyed hash -
  raw IPs are never stored. Fields are injection-sanitised. Daily files,
  self-pruned (retention_days, default 90). first_party: off on the Plugin
  Config page disables recording.
- The Visitor Statistics page reads first-party data as its primary source;
  the web-server log survives as the fallback/enrichment (the response's
  `source` field says which). Operator/manager traffic is excluded from the
  visitor headline; asset noise (favicons, images) no longer pollutes top
  pages. Note: first-party history starts at this upgrade.
- Bonus: an unhandled processor error now answers a clean, logged, recorded
  500 instead of a headerless crash.

Fix - visitor stats message when the log exists but is unreadable
- "No access log found" hid the actionable problem on panel hosts; the
  fallback path now says the log EXISTS but is not readable by the
  web-server user, and points the owner at --resolve-log.
