Release 0.7.13 - STABLE: public QR component + manager polish from the demo review

Channel: STABLE - the whole fleet takes this on the next upgrade run.
A short, demo-driven follow-up to 0.7.12: the bundled QR library becomes
a public site asset with a content component, and a handful of manager
interaction fixes from reviewing the live demo.

QR on public pages (SM147, the deferred item, now done)
- The bundled, self-contained QR library (qrcode-generator, MIT - no CDN,
  no host dependency, in the SBOM) is promoted from a manager-only file to
  a shared PUBLIC asset at /assets/qrcode.js. The manager 2FA QR loads it
  there now too.
- A new built-in `::: qr data="..."` content component renders a QR (link,
  payment URL, wifi string, ...) on any Markdown page, with an optional
  size. The QR is drawn client-side from the module matrix - the value is
  never inserted as markup, so there is no injection surface.
- The processor gained a built-in-component fallback: `::: name` resolves
  against the active layout's components/ first, then
  lazysite/templates/components/, so a built-in works on any layout and a
  layout can still override it.

Manager polish (SM150, from the demo review)
- Users tree: clicking an account NAME opens its editor - consistent for
  top-level accounts and sub-accounts (a leaf name did nothing before). The
  accent disclosure triangle is the obvious control to expand a sub-tree;
  the explicit Configure button stays, de-emphasised.
- Groups: editing a group no longer reloads and collapses the list - a
  capability toggle or a member change updates just that group's summary
  and pills in place.
- Permission-denied messages say "an administrator can grant it on the
  Groups page" instead of "an operator" (audit trail, sessions & keys,
  notifications).

Verification
- Full suite green; bench and coverage gates pass; tidy clean.
