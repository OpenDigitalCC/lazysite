Multi-site: bare-docroot scan excludes other domains' content roots (SM151 §7)
- A primary/default host with no content_root scanned the whole docroot, so
  its sitemap and search enumerated every client subtree's pages. The page
  scanner (registries and search) now skips any directory that is a declared
  content root - the base content_root or any alias.<host>.content_root.
- So a bare/default host lists only its own docroot-root content, and no
  domain lists a nested sub-domain's pages. Non-domain directories under the
  docroot stay part of the bare host's own content.
- Single-site installs declare no content roots, so nothing changes for them.
- This closes the second finding of the adversarial cross-domain-leakage
  review; the first (boundary-safe confinement against superstring-sibling
  escapes) shipped in 0.7.14.
