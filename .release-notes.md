Fleet upgrade channels and policy - update_policy, --force-security and the sites listing (SM139 increment 3)

`lazysite upgrade --all` is now safe to drive from cron: each site opts in
with `update_policy: auto` in lazysite.conf (default `manual` = skipped
and logged per site), and auto sites still pass through install.pl's
existing update_channel gate (exit-3 skips are reported as skips, not
failures). Channel: edge.

- New conf key `update_policy: auto|manual` (default manual). Setter:
  `install.pl --policy auto|manual --docroot D` (audited as `policy-set`,
  same shape as --channel); seeded into fresh confs and
  starter/lazysite.conf.example.
- `lazysite provision --policy auto|manual` writes the conf key and caches
  `policy=` in the site registry entry (the conf stays authoritative).
- `lazysite upgrade --all --force` overrides both policy and channel (as
  before, install.pl records the channel override in the site audit log).
- `lazysite upgrade --all --force-security` overrides both gates but ONLY
  when the payload release-manifest.json declares
  `"security_critical": true` - stamped at build time with the new
  `tools/build-manifest.pl --security-critical` flag; refused with a clear
  message otherwise. The fleet answer to "force a security fix out now".
- New `lazysite sites` verb: registered sites with owner, live
  channel/policy, installed version (.install-state.json) and docroot.
- Tests: new t/tools/29-cli-fleet.t (policy x channel matrix, force and
  force-security paths, refusal message, sites listing); all gates green.

Apt repo publication (stable/edge suites) from the SM139 increment-3 line
remains open pending the repo-hosting/signing decision.
