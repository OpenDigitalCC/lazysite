Release 0.7.16 - EDGE: security hardening round 1 (SEC-2026-07)

Channel: EDGE - a dedicated security-hardening release, stacked on 0.7.15 for
the same field test on edge-channel sites. Beta and stable sites do not take it
automatically; given it fixes three criticals, promote it up the ladder (beta,
then stable for the production fleet) once the next scheduled security re-check
confirms it in the field.

What this is
- An 11-agent security review (static across every surface + black-box probers
  on a live multi-account, multi-site instance, then a focused RCE/OS-access
  follow-up) was run against 0.7.15. Every critical, high and medium finding is
  fixed here, each with a regression test. The durable register of what the
  round covered is security/audit-register.json. Exploit detail is kept out of
  the repo by policy.

Criticals
- RCE-1: the manager plugin runner no longer executes an arbitrary on-disk file
  - plugins resolve only through a canonical registry (SM152 groundwork).
- C1: a content-only account can no longer reset another account's password;
  the users action requires a user-management capability and password resets are
  actor-confined to the caller's delegated sub-tree.
- C2: a content include can no longer read the lazysite/ secrets tree; includes
  are confined to the content root and refuse the management tree.

Highs
- H1-H4: the cookie/manager path is now capability-gated (parity with the token
  model), state-changing actions are POST-only (CSRF), the file-layer containment
  check is boundary-safe (no sibling-prefix escape), and the generic editor is
  denied the sensitive lazysite/ subtrees while keeping the managed authoring
  areas reachable.
- H-SSI / H-HTACCESS: the shipped vhost templates drop SSI #exec and
  AllowOverride All, and active-content/server-config extensions are refused on
  write.
- H5: front-matter title/subtitle/author and the manager breadcrumb are
  XSS-escaped.
- H6: the remote fetch re-validates every redirect hop (SSRF).
- H7: the dev server confines its static handler, denies the lazysite/ tree and
  traversal, binds loopback by default, and no longer wedges on a bare auth POST.

Mediums
- M2 dav_scope enforced on MCP/API; M4 logout invalidates the session server-
  side; M5 groups re-resolved per request; M-TAR backup restore drops setuid/
  world-writable modes; M1 cross-domain include confinement (with C2).

Low/info
- Manager plugin-list + alias-redirect output escaped; the FastCGI pool unit is
  systemd-sandboxed. A login throttle and OAuth register rate-limit are deferred;
  the secret-file chmod TOCTOU is accepted (shielded by the 02770 dir). All
  recorded in the register.

Verification
- Full suite (203 files, 3680 tests) green; bench within tolerance; coverage
  gate green; perltidy clean across all changed and new files. No restore
  rehearsal (per-stable-cycle only; this is edge).
