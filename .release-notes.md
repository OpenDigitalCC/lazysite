Release 0.9.0 - STABLE: cross-plane permission consistency + service killswitches

Channel: STABLE. A security-hardening release on 0.8.0. Fixes a reported
token-path regression, aligns capability enforcement across every access plane,
and puts each remote surface behind an operator killswitch (default off).

BREAKING - opt-in required after upgrade
- Every network surface beyond the public page render is OFF by default. Enable
  what you use in Site settings -> Services (or lazysite.conf): mcp_enabled,
  oauth_enabled, control_api_enabled, token_exchange_enabled = enabled. WebDAV
  was already opt-in.
- WebDAV nav / form-config editing now needs manage_nav / manage_forms (matching
  the API/MCP planes), not manage_config. Grant those where needed.
- Agent feedback over MCP is now a `feedback` capability (off by default).
- The manager UI, public page render, and existing content/theme/layout grants
  are unaffected.

Token-path regression fixed (reported on 0.8.0)
- The SM127 gate wrongly refused introspection (whoami / describe-capabilities)
  for manager-linked accounts, and refused agent accounts (manager `ui`
  capability but interactive login disabled). It now blocks only accounts that
  can actually use the interactive UI and never blocks introspection, on both the
  control-API and MCP channels.

Service killswitches
- MCP, OAuth, the control-API token path and token exchange each gain a conf
  killswitch (default off), read through one shared helper. A disabled surface
  refuses before doing any work and discloses nothing. Toggles live in the
  Services section of the config page (the manager landing page).

Cross-plane capability consistency
- WebDAV nav.conf -> manage_nav, form configs -> manage_forms (was manage_config).
- site-backup-create/upload/apply are POST-forced (closed a CSRF-free-GET gap).
- A WebDAV drift-guard test, an in-tool actor backstop for the users tool's
  group/capability-mutating verbs, and a stronger capability-gate guarantee.

SSRF guard on domain-check + tenant-token isolation (from the 0.8.x line)
- domain-check refuses outbound probes unless every resolved address is public
  (closes DNS rebinding / IP-literal / metadata / RFC1918); a control-API token
  cannot authenticate against another site's docroot.

Everything in 0.8.0 is included.
