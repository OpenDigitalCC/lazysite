Release 0.9.13 - BETA: site integrity, capability clarity + connector reliability

Channel: BETA. A broad reliability + clarity beta on top of 0.9.12, gathering the
capability/manager, connector, site-package and content-history work. No BREAKING
change and no migration. Stable-channel sites are unaffected until these promote.

Site integrity
- Engine-served system pages (SM201): the auth/error pages (login, claim,
  402/403/404) now live in the protected lazysite/templates/system/ tree and are
  served with a fallback - a content-root copy overrides, else the docroot-root
  copy, else the protected default. So a deleted or never-seeded copy self-heals
  instead of 404ing (an agent can no longer break /claim by tidying "boilerplate"),
  and a content-rooted subdomain without its own copy still serves them. A
  content-root copy still overrides for customisation.
- Site-package migration completeness (SM193): a site package can now be
  DOWNLOADED by a token client (site-backup-download, manage_domains, confined to
  the site-package namespace), completing the agent create -> download -> upload ->
  apply migration loop; applying a package KEEPS the target domain's own
  site_url/site_name by default (a migration, not an identity clone - opt into the
  source's with adopt_identity); and apply now mirrors the layout's theme assets so
  an applied site renders styled immediately.

Connector reliability
- Distinct sign-in failures (SM200): a refused MCP call now names the cause -
  sign-in-incomplete (finish authorising / paste the connect code), credential-
  invalid, token-expired, or token-invalid - instead of one opaque reason.
- Fewer first-attempt failures (SM200): the connect code is valid 30 minutes (was
  15) and surfaces its expiry; the setup panel + docs now tell the operator to open
  a NEW chat if the assistant does not see the tools (the tool list is fixed when a
  chat opens). Deploy-time check: lazysite-check flags a remote service enabled with
  an unset / non-https / trailing-slash site_url, which would make the discovery
  docs advertise broken endpoints.
- Connected-detection + capability-aware discovery (SM196): the "waiting to
  connect" indicator flips at authorise time; the onboarding copy is agent-neutral;
  and an authenticated tools/list is filtered to the tools the session can invoke.

Capability + manager clarity
- The permissions grid ticks a capability x channel cell only where the capability
  has a real surface on that channel (SM197); a group that grants capabilities but
  has no members is flagged as inert (SM198); hidden capability-gated areas show a
  "grant X to enable" hint to an operator who can grant it (SM191).

Content history + stats
- Content-history status is a real health probe: it distinguishes enabled-and-
  healthy from "switched on in config but the repository is missing/unusable" (a
  network-interrupted enable) and from a degraded/paused repo.
- The visitor-stats classifier reclassifies SPA/build-manifest and secret-fishing
  probe noise, and drops referrer spam from the reports (SM192).

From 0.9.12 the 0.9.0 posture is unchanged (remote surfaces off by default; enable
in Settings -> Services).

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
