Release 0.6.1 - Content tools, backups, and change awareness

A feature release on the 0.6.x line. All gates green; channel: edge.

Content authoring
- Multi-step (wizard) forms (SM098). A `--- step ---` line inside a `:::form`
  splits it into steps with Back / Next and per-step validation; the form still
  posts once, and without JavaScript every step shows and it still submits.
- Page alias redirects (SM134). A page can declare `aliases:` in its front matter -
  old or alternate URLs it should also answer to - and a request for one returns a
  301 to the page's canonical URL. A real page always wins over an alias; the
  redirect target is always the declaring page's own URL.

Backups
- Full-system backups. Alongside content backups, a "full" backup captures the
  whole site including configuration, accounts and themes/layouts - for disaster
  recovery and for migrating a site to another domain. Restore is a system-user
  operation: install.pl --restore-full <file> --docroot X --domain Y extracts a
  full backup and rewrites the site domain (build on a temporary domain, then move
  content, config and accounts to the final one).
- The Backups page is consolidated into typed sections: Content (create / restore /
  download), Full-system (create / download; restore via the CLI), and a pointer to
  the Appearance page for theme/layout snapshots.

Dynamic content
- Show the visitor's IP (SM135). A [% client_ip %] template variable (the
  X-Forwarded-For first hop behind a proxy, else the connection address) plus a
  `nocache: true` front-matter flag that renders a page fresh every request. Show
  the IP inline, or via a small nocache JSON endpoint fetched by client-side script.

Change awareness
- Recent-change markers (SM103, phase 1). The Files and Users pages show a small
  dot next to a row changed within the last day, with a when / who / what tooltip,
  driven by a new recent-changes control-API action reading the audit-log tail.
