Release 0.7.4 - Content history: the git backend (SM085 phase 1)

Every content write is now a commit; any version is viewable, diffable and
restorable; and an opt-in plugin syncs the history to a private remote -
without exposing a line of git vocabulary. All gates green; channel: edge.

Content history (core)
- Enable on the Backups page ("Content history"): the docroot is versioned
  with the repo INSIDE the protected lazysite/ tree - no .git under the
  docroot, nothing for a web server to leak.
- Versioned: your content plus lazysite.conf and nav.conf. NEVER versioned
  (enforced at init, self-healed, and probed by lazysite-check as a
  security FAIL): auth/, forms/, plugin credential files, caches, logs,
  backups - the history is safe to push by construction.
- Every manager/DAV/connector write commits with the acting user as
  author; backup restores are commits too (history, never erasure).
- Files app: per-file History - list, View any version, Diff, Restore.
  Restore routes through the normal save path (cache invalidation, alias
  reindex, audit, and its own history entry).

Remote sync (git-sync plugin, opt-in)
- Remote URL + branch + token (the token never appears on a command line,
  in git config, or in a stored file beyond the 0660 conf - injected via a
  transient environment-read helper, removed after every action).
- Push and Pull on demand; Test connection reports in plain language.
- Conflicts without git-speak: a diverged pull stops with "These pages
  changed in both places: ..." and Keep mine / Take theirs buttons; a
  safety snapshot precedes any applied change; caches and aliases refresh
  after every pull; outcomes audited.

Also in this release
- The plugin-action mechanism gains declared-choice buttons (generic - any
  plugin can now ask an either/or question safely).

Validation: docs/review/2026-07-11-field-validation.md is the human review
checklist for the whole 0.7.x line (debs, onboarding, pools, fleet,
sessions, aliases, history + sync round-trip).
