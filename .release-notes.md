Release 0.7.19 - EDGE: domain config check + domains panel fixes

Channel: EDGE - a domain-configuration check plus live-testing fixes and
usability on the SM154/SM155 domains admin. Stacks on 0.7.18.

Domain configuration check (SM156)
- A Check button (and `lazysite-domains check <host>` / a domain-check
  control-API action) reports whether a registered domain is configured to
  serve THIS install live: DNS resolves, points to this server, a trusted HTTPS
  certificate terminates for the host, and an HTTPS request lands on this
  instance (a new public CORS-open /.well-known/lazysite-instance.json marker
  echoes a stable per-install id). The server does the DNS/IP/TLS/marker work a
  browser cannot; the panel adds a browser-side probe for the visitor's view.
  The outbound probe is bound to registered hosts (no SSRF) and manage_config-
  gated - which also tightened domain-preview's registered-host check.

Preview works on a live (wrapped) deployment (bug fix)
- The Preview shelled $LAZYSITE_PROCESSOR, which the Apache/Hestia rewrite (and
  the dev server) set to the originally requested CGI - manager-api itself when
  a preview runs - so the preview re-entered manager-api with auth stripped and
  showed {"error":"Authentication required"} instead of the page. Both previews
  (page and domain) now resolve lazysite-processor.pl by name in that cgi-bin.

Alias mirrors its canonical's presentation (bug fix)
- Aliasing a sub-domain showed the DEFAULT site's title, because the alias
  copied only content_root + site_url. An alias now copies every per-host
  override the canonical set (title, theme, layout, nav, search), so it presents
  identically to the domain it aliases.

Content folder optional; reserved paths defined once
- A domain with no content folder registers and serves the DEFAULT site (the
  engine already treated an empty content root as the docroot root). The "not
  the lazysite/ tree" guidance is replaced by an actual server-side block,
  driven by a single Common::path_is_reserved / @RESERVED_ROOTS definition.

Per-domain template variable
- The render stash exposes `domain` - the sanitised host being served (primary
  or alias) - so one content folder can branch per domain:
  [% IF domain == 'clienta.com' %]...[% END %]. Cached per host; DNS-alphabet
  only, so it can never carry markup.

Preview: open the live site
- The preview keeps its in-session server-side render (works pre-DNS) and adds a
  link that opens the real domain in a new tab, for once it is live.

Domains panel usability
- The add panel is full width and table-styled (was a half-width card); the
  Site address auto-derives https://<host> as you type the domain; fields carry
  friendly labels and FQDN guidance. The table shows a curated column set and
  scrolls inside its own box, so a new domain's buttons no longer run off the
  page. The inline edit row is a styled panel that pre-fills each field's
  current value (inherited values shown as a greyed placeholder).

Hestia update-all is template-authoritative
- lazysite-hestia-update-all.sh discovers via lazysite-hestia-list.sh
  --template-only (the Hestia web template is the sole authority), so a domain
  moved off the lazysite-app template is not updated; any marker-only domains it
  excluded are reported for reconciliation.
