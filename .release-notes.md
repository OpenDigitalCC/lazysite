Release 0.9.2 - BETA: manager-UI grantability + data-loss + info-leak fixes

Channel: BETA. The beta candidate for the 0.9.x security-hardening line,
promoting the work validated on edge (0.9.0/0.9.1). Bed this in on beta before
promotion to stable (which is a channel bump of this same build, no re-cut).

0.9.1 (edge) fixed the Config-page save bug (SM042: the service-killswitch
toggles persist). 0.9.2 adds three fixes a validation sweep + a partner site
agent surfaced:

- Capabilities enforced but ungrantable in the UI: `feedback` and
  `notifications` were missing from the Groups capability grid (no operator
  could grant them from the manager UI). Both grids now list the full set; a
  parity test fails the build on any future drift from @CAP_KEYS.
- Form "Edit targets" silently erased legacy inline targets (data loss); the
  save now preserves them (backend-enforced).
- nav-read leaked the server-absolute path (filesystem layout + system
  username) to token clients; now returns the docroot-relative path.

Upgrade checklist for an existing site (the 0.9.x breaking changes are
operator-recoverable, not auto-migrated by design):
- Enable the surfaces you use in Site settings -> Services (mcp_enabled,
  oauth_enabled, control_api_enabled, token_exchange_enabled).
- Grant manage_nav / manage_forms to any group whose WebDAV accounts edit
  nav.conf or form configs (was manage_config).
- Grant `feedback` to any group whose agents use MCP submit_feedback.

Everything in 0.9.0/0.9.1 is included.
