Release 0.5.39 - Agent capability discovery + strict api/mcp channel gating

Full suite green (2,219 tests, 148 files); perlcritic clean (severity 4 +
security theme); compile sweep green; bench gate green; coverage gate green;
strict SBOM gate green.  Channel: edge.

SM126 (agent onboarding & capability discovery), phases A-E:

- Capability map. A connecting agent can call ONE endpoint - the MCP tool
  describe_capabilities or the control-API describe-capabilities action - and
  get the whole picture: the four channels (all enforced), what each capability
  unlocks (which MCP tools, control-API actions and WebDAV paths), task recipes
  for common jobs (install a theme, author a layout, publish a page, wire a
  form), the engine-owned paths it must not write, and - under "holds" - what
  its own account currently has. No more discovering the rules by trial and
  error. Derived from one source of truth and drift-checked against the live
  tool and action maps. The same model, for humans, is generated into
  docs/reference/capability-map.md with copy-pasteable quickstarts. When a
  capability is missing, the MCP and control-API denials now point back at
  describe_capabilities so a refused agent has a next step.

- Host dependencies. tools/gen-host-deps.pl generates a Debian package list
  (docs/reference/host-dependencies.md) from the SBOM data, and
  lazysite-check.pl --dependencies reports present-vs-missing on a host with the
  apt-get line for anything absent - so "what must I install here" is answered,
  not discovered.

- Strict channel enforcement (security). The api and mcp channel capabilities
  were modelled but not enforced at the transport. Now a control-API token must
  hold the api capability and an MCP session must hold mcp, enforced ahead of
  the per-action check. Introspection (whoami, describe_capabilities) stays open
  so a capless agent can still self-diagnose. The manager UI (cookie session) is
  unaffected.

  OPERATOR ACTION: a token or MCP partner must now hold the api / mcp capability.
  The standard partner onboarding already grants both, and the default seed
  groups agent-ai / mcp-ai carry them, so normally-provisioned partners are
  unaffected - but verify any hand-provisioned token or connector accounts hold
  the channel capability before upgrading.

Also: the control-API whoami and the manager permissions grid now derive from
the canonical capability list (whoami had dropped delegate_sub_user_creation).
