Release 0.7.24 - EDGE: site packages, manage_domains, nav domain-awareness

Channel: EDGE. A larger batch: portable site migration, a new capability, and
nav/audit/backup refinements from live-testing. Stacks on 0.7.23.

Portable per-domain site packages - move a whole site (SM158)
- Package one domain's site (its content, nav, the theme + layout it uses, and
  its presentation settings) into a portable file, and apply it to another
  domain or another instance. Turns an agency demo into a client's live site, or
  copies a site between domains. Excludes plugins, instance settings and secrets,
  so it is self-service and safe to hand over.
- Apply extracts safely (isolated staging, drops symlinks, rejects path
  escapes), snapshots the target first, installs the theme/layout only if
  missing, and records the result in content history.
- Surfaces: control API (site-backup-create/upload/apply), MCP (site_backup /
  site_apply, with a migrate-site recipe), CLI (lazysite-site backup|apply).
  site-backup-upload is the first backup upload (backups were server-only).
- Docs: features/configuration/site-migration.md (user) and the connector tool
  doc (agent).

A manage_domains capability, carved out of manage_config (SM160)
- Domain management and site packages are their own capability now, so a
  delegated domain/site operator no longer needs the broad manage_config (which
  also covers auth-secret rotation, the bad-URL blocker, backups and plugins).

Navigation editor is domain-aware, with a clearer add box (SM159)
- Pick which domain's nav to edit; the add-item inputs move behind an
  "+ Add menu item" button that expands a labelled box.

Also
- Every backup file carries a lazysite- prefix.
- The audit trail records a meaningful target (host / config key / backup kind /
  login site) instead of a bare "/".
- On the Users page, clicking an account name expands the row; Configure opens
  the editor.
