Release 0.9.11 - BETA: field-issue fixes (login loop, raw-content write guard, discovery gating)

Channel: BETA. Reliability and correctness fixes on top of the 0.9.10 stable line,
from field reports. No BREAKING change and no migration. Sites on the stable
channel are unaffected until these promote.

- FIX (login loop): a site could bounce every page to the login screen while the
  browser still held the JS session marker - the marker cookie (lzs_session)
  outlived the real signed session (for example after the auth secret was rotated,
  which invalidates existing cookies), so the login page reported "already signed
  in" and hid the form while every request re-bounced. Both bounce points now
  clear the marker (Set-Cookie ... Max-Age=0), so a stale marker can no longer
  strand a signed-out user. (SM188)
- HARDENING (content integrity): the write path now refuses raw-mode content pages
  - a page whose front matter forces an HTML/XHTML/SVG content_type via api:/raw:
  - on both the manager save and WebDAV PUT (415). This keeps ordinary content
  pages themed and on-policy (no bypassing the layout or the no-CDN rule) and adds
  defence in depth; the browser content-sniffing vector was already contained by
  the raw-mode content-type downgrade. Extends ADR 0006 to the write path. (SM189)
- FIX (discovery correctness): the .well-known/oauth-authorization-server and
  oauth-protected-resource discovery documents now return 404 when OAuth is not
  enabled, rather than advertising - and render-caching - endpoints that only
  answer the disabled-service response. They serve normally when oauth_enabled is
  on. (SM190, partial - the ai-partner code-serve and the lazysite-check endpoint
  probe remain follow-ups.)

From 0.9.10 STABLE the 0.9.0 posture is unchanged (remote surfaces off by default;
enable in Settings -> Services).

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
