Release 0.9.16 - BETA: token-lifetime control, live-config AI discovery, discovery hygiene

Channel: BETA. A small, focused release on top of 0.9.15: an operator-set access-
token lifetime with renew-on-use, a code-served AI-partner discovery document, and
an MCP discovery-hygiene fix. No BREAKING change and no migration; the secure
defaults are unchanged. Beta-channel sites take this; stable sites are unaffected
until it promotes.

Access-token lifetime (SM212)
- The lzs_ machine token (pairing exchange; WebDAV + control-API Basic auth) had a
  fixed 24-hour life and no renewal, so an automation account that was not used
  daily had to be kept alive by a cron. An operator can now set a per-account
  token lifetime (token_ttl) up to a hard 30-day ceiling, and an account that
  carries one also gets sliding renewal: an in-use token has its expiry pushed
  forward on use, so it never lapses while active - only a full idle window
  expires it. No cron, and a better posture than one (the secret is not copied
  into a scheduler; it stays revocable and audited).
- The default is unchanged: an account with no token_ttl keeps the hard 24-hour
  window and does not slide. The 30-day ceiling is enforced centrally, so no
  account can outlive the OAuth refresh horizon. Set it from the manager Sessions
  & keys page (a per-key Lifetime control: 24h / 7d / 30d) or the CLI
  (set <user> token_ttl 30d).

AI-partner discovery is code-served (SM190)
- The /.well-known/ai-partner bootstrap is now generated from the live config
  rather than a static page: it lists only the endpoints whose service is enabled
  (WebDAV, MCP, control API, token exchange) and is served no-store, so it can no
  longer advertise an endpoint that is switched off or drift from the real grant.
  This completes SM190 (the OAuth-discovery gate and the deploy-time endpoint probe
  shipped earlier).

MCP discovery hygiene (SM210)
- tools/list now returns only the introspection subset (whoami,
  describe_capabilities) to an unidentified caller - an anonymous request or an
  unrecognised / revoked token - instead of the full tool vocabulary. Enforcement
  was always intact (every tools/call gates on capabilities); this aligns
  discovery with identity so the full write surface is not advertised pre-auth.

Also: the SM207 design-transfer briefing is closed out as superseded by SM208's
integrations namespace (shipped in 0.9.14).

From 0.9.15 the 0.9.0 posture is unchanged: remote surfaces (WebDAV, control API,
MCP, OAuth) are off by default; enable them in Settings -> Services.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
