Release 0.9.17 - BETA: durable stats store + trends, and sudo-safe permissions + repair

Channel: BETA. Two features on top of 0.9.16: a durable per-day visitor-stats store
with month-on-month trends, and permissions helpers that stay safe under sudo plus a
repair tool for drift. No BREAKING change and no migration (the stats store rebuilds
itself from existing data on first run). Beta-channel sites take this; stable sites
are unaffected until it promotes.

Visitor stats: durable store + trends (SM213)
- The aggregates are now stored long-term as one small JSON file per day under
  lazysite/stats/ (outside the clearable cache), with monthly rollups and an index -
  durable, per-day addressable and downloadable, with no cap to hit and nothing for
  an operator to configure. The 5000-event ring was only ever a recent SAMPLE, never
  the aggregates; the export now says so with self-describing fields (data_from, and
  sample: {from, to, count}) and retires the misleading events_capped flag.
- analyse_visitors (control API + MCP) gains index / day=YYYY-MM-DD / month=YYYY-MM
  selectors alongside the windowed view, and a month-on-month series. The manager
  Stats page shows a month-on-month indicator.
- Classification is now visitor-level: a token that probes a non-existent path is
  marked a scanner and its whole session (including a spoofed referrer) is excluded
  from the people/referrer figures, not just the probe; 404s split into plausible
  missing pages (kept by path) vs a junk scanner-chorus count.
- Privacy commitment codified: lazysite installs no trackers (no analytics JS,
  cookies, fingerprinting or third-party requests); the durable day files hold
  aggregates only, never per-visitor records; visitor keys are daily-salted.

Permissions: sudo-safe helpers + updater, and a repair tool (SM215)
- A helper or update run under sudo no longer leaves files owned by root that the
  web-server CGI cannot access. secure_write_perms makes a just-written file inherit
  its provisioned directory's owner+group and, when run as root, sets the owner too;
  applied across the credential / settings / groups writers, and install.pl's
  config-replace path now preserves the file's owner as root.
- lazysite-check --fix is the canonical repairer (it applies chmod always + chown as
  root via a handover mode that preserves the CGI's access, then re-runs every
  check), and it now also covers the new lazysite/stats/ dir. lazysite-fix-perms is a
  friendly front-end to it: dry-run by default, --apply to repair. Run it once on a
  site whose lazysite/ ownership or modes have drifted.

Also filed for the roadmap (not in this release): SM214 (a form-list read action for
token clients) and SM216 (quarantine-based form spam controls).

From 0.9.16 the 0.9.0 posture is unchanged: remote surfaces (WebDAV, control API,
MCP, OAuth) are off by default; enable them in Settings -> Services.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
