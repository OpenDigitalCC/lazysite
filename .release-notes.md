Release 0.8.0 - STABLE: multilingual + domain access + cache correctness, certified

Channel: STABLE. The second stable release, cut from the 0.7.28 beta on completion
of the 2026-07-18 eight-dimension non-functional review. It promotes the whole
0.7.x line to the stable channel and clears a Commercial signoff on all eight
dimensions.

What it promotes to stable
- First-class multi-site: many domains on one instance, per-host content roots and
  confinement, delegated domain management.
- A domain-owned access-control model with per-user locks (SM165) and compound
  groups (SM121).
- Content history that follows renames and never leaks across delete/recreate
  (SM175).
- The complete multilingual language-set feature (SM179 P1-P8): sibling
  per-language content roots, engine-supplied switcher + hreflang, layout chrome
  strings, engine-emitted-chrome i18n, translation coverage, and agent
  discoverability.
- Conf-aware cache correctness: a conf change invalidates the page cache under any
  process model; per-host caches are managed in the manager.

Certification and the security fix it surfaced
- All eight dimensions clear a Commercial signoff; every 2026-07-10 refusal is
  verified still cleared (reliability SLO/RTO/RPO, the pentest gate, documentation
  currency, the Declaration of Conformity and the SBOM own-licence).
- The review caught and this release fixes a serious stored-XSS / response-header
  injection: a page's front-matter lang: reached <html lang> and the
  Content-Language header unescaped, letting a content-only partner run script in
  every visitor's browser. Now sanitised to a bare language tag; a domain-add CRLF
  gap closed the same way.
- Further hardening: the manager-API now applies the same in-app trust gate as the
  processor, so forged X-Remote-* identity headers are ignored unless the auth
  wrapper vouched for them; a raw/api page can no longer declare an HTML/SVG
  content_type (downgraded to text/plain at serve time); backup restore excludes
  the lazysite/ control tree so a crafted tarball cannot overwrite auth/config; and
  session/user/key revocation is forced to POST for CSRF completeness. Operators on
  0.7.27 / 0.7.28 should upgrade for all of these.
- An adversarial security-testing breadth pass added structural guarantee tests
  (no ungated action, cookie/token capability parity, write-channel guard routing,
  cross-channel dav_scope enforcement) and negative tests (sub-user escalation
  confinement, path-traversal sweep, login-rate-limit fail-open).

The Declaration of Conformity is finalised for 0.8.0 and signed at the cut.
