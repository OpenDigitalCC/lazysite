# 0.10.2 - EDGE

**Things the platform knew and did not say.**

Every change in this release closes a gap between what lazysite knows about
itself and what it tells the person or agent asking. Most were found by partners
and site agents working real sites, each of whom did something reasonable with
information that was accurate and incomplete.

## The theme a domain is bound to now gets published

Binding a layout and theme to a domain wrote the binding and published no assets,
so a secondary domain served a `404` stylesheet. The symptom was misleading: the
layout **was** applied and rendered its header, nav and footer correctly, so an
unstyled page read as "no layout" when it was a missing CSS file.

`domain-set` now mirrors the theme's assets under **that domain's own layout**,
which is the case that failed - a secondary domain running something other than
the instance-wide layout. The primary site's presentation is untouched, which is
the trap in the previous remedy: re-activating to fix a secondary domain switched
the primary site's theme.

The layouts briefing gains a **multi-domain** section, because the old advice
("if the mirror 404s, re-activate to rebuild it") is right for one site and
damages a different site otherwise.

## Errors that pointed the wrong way

**A WebDAV write to an unwritable directory** returned a bare `500`, which cannot
be told apart from a scope refusal or a genuine fault. It now returns `507` and
names the condition, so an operator fixes permissions instead of an agent
reporting a policy problem that does not exist.

**An unrecognised control-API action** was reported as "not available to token
clients" - the same message as an action that exists and is simply cookie-only.
Those point in opposite directions: ask for a grant, versus fix your request.
They are now distinct.

**The capability map** returned what the platform offers and what your account
holds, side by side, and readers flattened the two. A `false` now says it means
"not granted to this account", never "not available in lazysite" - and a channel
you hold whose site service is switched off now says so, instead of reading as
available.

## Discoverability

- **A documentation index** in `describe_capabilities` and a `/docs/` page. A
  site publishes around thirty documents; a partner was told about three.
- **Form submissions** no longer read as a write-only store, and `/docs/forms`
  now covers reading them, long-text and file intake, and what happens when one
  arrives.
- **Submission notification is documented.** Every submission raises one -
  manager bell, plus chat where configured - and nothing said so, so integrators
  designed polling loops.
- **Browser-origin calls** have a stated position instead of a silent absence,
  and a preflight is now refused explicitly rather than failing opaquely.
- **`raw:` does not mean raw.** The refusal now names the static-file route, and
  existing affected pages are reported by `validate_page` and `audit_site`.

## Manager

- **"Independent of creator"** is now **Content access**, and shows which
  accounts currently cap this one - so an operator can see whether the setting
  would change anything.
- **A theme or layout used by a sub-domain** is marked in use and names the
  domains, instead of offering a Delete button that the server then refuses.

## Under the hood

Four new drift guards: no permissive CORS on the authenticated surfaces, the
known-action set pinned to the dispatch chain, the MCP/control-API surface shape
pinned against a recorded baseline, and a feature-request status that contradicts
its own note now fails the lint.

The backlog itself was corrected: 25 items were marked as open work while their
own notes recorded them as shipped, so open items drop from 40 to 24.

## Upgrading

No configuration changes. `form-list` gains `row_count`; the `rows` key remains
as a deprecated alias for one release and will be removed.
