Release 0.7.26 - EDGE: content history + domain access model + manager batch

Channel: EDGE. A large batch: content history that follows renames, a
domain-owned access-control model with per-user locks, compound groups, and a run
of manager improvements. Stacks on 0.7.25.

Content history follows renames (SM175)
- Moving a file now carries its version history to the new path, and a delete
  ends that file's history - a later file created at the same path starts clean
  and never inherits the deleted one's past. Recorded as first-class moves across
  the manager, MCP (rename_page) and WebDAV, so the Files "History" panel lists
  the full lineage and can view, diff and restore even pre-rename versions. Agent
  guidance steers connectors to the move tools rather than recreate-and-delete.

Domain access control: domains own who may manage them, with locks (SM165)
- Each domain names the groups allowed to manage it and the users locked to it,
  edited on the Domains page. A delegated editor is confined to the content roots
  of the domains their groups allow; a lock narrows them to one domain; a domain
  with no allowed groups is operator-only. A created sub-user (e.g. a delegated
  MCP agent) can never out-reach its creator - its scope is intersected up the
  created_by chain and it cannot hold a capability the creator lacks. The same
  resolution enforces on the manager UI, control-API tokens, MCP and WebDAV.

Compound groups (SM121)
- A group can now contain another group; the sub-group's members inherit the
  parent's capabilities and domain access, so roles compose instead of
  re-granting the same permissions across many groups.

Manager improvements
- Themes: install no longer auto-activates, and switching away from a theme backs
  it up only if you actually edited it (SM176).
- Navigation: saving the menu refreshes the page cache so it publishes
  immediately, and the nav editor states exactly which file it is editing (SM168,
  SM169).
- Audit: a sub-user manager sees a scoped audit view of their own team's activity
  without the full audit permission (SM173).
