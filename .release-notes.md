Release 0.9.5 - BETA: in-manager form-submissions viewer (SM182)

Channel: BETA. A small, low-risk feature increment on the 0.9.4 stable security
line. One functional change - a safe way to read form submissions from the
manager - plus two recorded proposals for later. Cut to beta to bed in before a
stable promotion; no BREAKING changes, no migration.

Functional change:
- SM182 - in-manager form-submissions viewer. Form submissions are written to
  lazysite/forms/submissions/<form>.jsonl, in the reserved lazysite/ tree the
  file editor refuses to open, so the data was unreachable from the UI. The
  plugin-config "View submissions" button now renders the store as an inline,
  escaped table instead of dead-ending at the reserved-file guard. A new
  control-API action `form-submissions` (manage_forms, read) parses the store
  server-side - docroot-confined, .jsonl only, no traversal - unions record keys
  into columns, caps at the most-recent 500 rows, and returns values verbatim;
  the client escapes every cell, so a hostile submission (e.g. <script>) renders
  as inert text. Gated at parity on both channels and enrolled in the audit-skip,
  write-path, capability-gate and cookie-read drift guards, with a backend
  parse/confinement test.

Recorded proposals (feature-request docs only, not yet built; target a later
release):
- SM180 - dormant-capability indicators: warn (never block) when a granted
  channel capability cannot work because its site service is disabled.
- SM181 - folder / URL-prefix protection: hold a whole folder/URL-prefix behind
  auth or as a draft, beyond today's per-page control.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
