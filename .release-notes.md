Release 0.6.3 - SMTP connection validation

A small, focused release. All gates green; channel: edge.

SMTP (SM137)
- Validate SMTP connection: a new button on the Plugin Config page runs a staged
  check against the saved SMTP settings and names the failing stage instead of a
  generic error - host (the name does not resolve), port (nothing answers there;
  a plain TCP probe runs first so a closed port is never mistaken for a TLS
  problem), TLS (the port answers but the TLS mode is wrong - the message says
  which mode to try), or auth (credentials rejected, with the server's code, or
  no password set). It never sends an email: connect, negotiate, authenticate,
  quit.
- Fix: the SMTP password typed into the new Password field (0.6.2) was stored
  but not merged into the delivery configuration, so authenticated sending kept
  failing. It now reaches the send path. If you configured SMTP auth on 0.6.2
  with the Password field, it starts working on upgrade - no action needed.
