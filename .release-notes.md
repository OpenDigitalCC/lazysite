Release 0.9.10 - STABLE: promotes the hardened 0.9.x line to stable

Channel: STABLE. A channel promotion of the bedded-in 0.9.9 beta - the SAME code,
now certified for the stable customer-rollout channel. No new functional change
at the stable step. Supersedes 0.9.4 as the STABLE release. No BREAKING change
and no migration from the 0.9.x betas.

This promotion carries forward the 0.9.5-0.9.9 line, most importantly 0.9.9:

- Data-loss hardening: atomic config + auth-store writes (temp + rename, never
  unlinking the real file), and every auth-store mutation serialised on a store
  lock - so concurrent saves cannot truncate lazysite.conf or the credential
  store, and cannot lose an update. Reads stay lock-free.
- SECURITY (details in the private advisory): manager file-path confinement
  hardened (the file-editor blocklist now matches the canonical resolved path);
  file-download and zip-download now enforce the read ACL and dav_scope that read
  applies; the account/group roster (principals) is capability-gated; and
  manage_domains / feedback / read_submissions grants, previously invisible to the
  cookie-manager gate, now take effect. Operators on 0.9.4-0.9.8 SHOULD UPGRADE.
- A disabled service answers 200 {ok:0, code:"service_disabled"} rather than a
  misleading 404.
- SM180 dormant-capability indicators; and the 0.9.5-0.9.8 features (submissions
  viewer SM182/187, site-package migration UI SM183, domains/site-package UX
  SM185, caps-within-session SM186).

From 0.9.4 STABLE the 0.9.0 posture is unchanged (remote surfaces off by default;
enable in Settings -> Services).

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
