Release 0.6.2 - Notifications: capability, XMPP delivery, and human-event notices

A feature release on the 0.6.x line. All gates green; channel: edge.

Notifications (SM136)
- A new "Notifications" permission gates the manager bell. Grant it to a group on
  the Groups page (the default user-managers group has it); users without it no
  longer see the bell.
- XMPP delivery: the new notify-xmpp plugin sends every operator notice to an XMPP
  address or group-chat room - one client account per site, configured like SMTP
  delivery (JID, password, recipient) on the Plugin Config page. Delivery is
  best-effort and time-boxed; the bell remains the record.
- More human-awaiting-a-response events now notify: a password-reset request when
  no SMTP is configured (previously a silent dead-end - operators are now told to
  issue a setup link), and agent feedback submissions, alongside the existing
  form-submission notices.

SMTP
- The SMTP delivery config (Plugin Config form and the handler wizard) now has a
  Password field - type it once, it is stored in the operator-only smtp.conf and
  never shown back. A password file remains available as an alternative.

Docs
- FEATURES.md brought current with the 0.5.x-0.6.1 lines (front-matter keys,
  caching, manager UI, backups + migration, forms, installer flags, the security
  model, and the version timeline); OPERATOR.md and README refreshed to match.
