Release 0.9.6 - BETA: site-package migration in the manager UI (SM183)

Channel: BETA. A UI-only feature increment on the 0.9.5 beta line. It exposes
SM158's portable per-domain site packages in the manager UI, so a human holding
manage_domains can perform the agency demo -> client hand-off without MCP or the
CLI. No BREAKING changes, no migration.

Functional change:
- SM183 (v1) - site-package migration in the manager UI. A per-domain "Export
  site" button on the Domains page; a "Site packages" panel on the Backups page
  to list, download, upload, apply and delete packages, with an apply preview
  (source host, file count, theme/layout/nav), a target picker (a registered
  domain or the primary site), a clean option, and a confirmation. Two new
  control-API actions - site-backup-inspect (read the manifest without applying)
  and site-backup-delete - both manage_domains + scope, confined to the
  lazysite-site- namespace so a full/content backup or an arbitrary path is
  unreachable. The package is the interface across surfaces: a package created
  by the MCP site_backup tool is applied by a human here, and a UI-exported one
  is applied by an agent.

Deferred to a later release (SM183 is partial): the dry-run content diff, a
one-click rollback + MCP site_apply snapshot parity, a target-readiness (domain
Check) step in the apply flow, an integrity sha, and the presentation-key remap
override.

Full gate before the build: suite + bench + coverage (every production CGI above
floors).
